# v1.0.0 Readiness Roadmap

> Generated from a documentation-vs-code audit across all 11 platforms +
> CITADEL + SDK (2026-08-05). Distinct from [ROADMAP.md](../ROADMAP.md),
> which tracks forward-looking feature phases — this document tracks the
> gap between what's **claimed** as v1.0.0/production-ready today and what
> the code actually does, and the work required to close it honestly.
>
> Every platform in [ROADMAP.md](../ROADMAP.md) and root
> [CLAUDE.md](../CLAUDE.md) is currently marked "✅ v1.0.0" or
> "production-ready." Per CLAUDE.md's own Quality Philosophy — *"Every
> feature must be production-ready, tested, and auditable when marked
> complete... 'Good enough for now' is never acceptable"* — this document
> exists because the audit found that bar is not yet met.

## How to read this

Each phase is a batch of work with a **time estimate** and a **definition
of done**. Phases are ordered by leverage and risk, not by platform —
do Phase 0 first regardless of which platform it touches. Time estimates
assume one engineer at a time; parallelizing across platforms (different
people/agents per platform) compresses wall-clock time roughly by the
number of parallel tracks, since most items are platform-independent.

## Phase 2 — Governance fail-open remediation (3–5 days)

CLAUDE.md: *"Code that weakens, bypasses, or silently fails the audit
path is a defect, regardless of whether tests pass."* 8 of 10 platforms
with a CITADEL client currently proceed anyway when MARSHAL evaluation
errors out.

| Item | Estimate | Notes |

## Phase 3 — Test coverage to the stated ≥70% bar (est. 2–4 weeks, needs per-platform scoping)

This is the largest unknown. Confirmed so far:

| Platform | Current coverage | Gap to 70% |
|---|---|---|
| apiguard | 40.8% | large |
| citadel | 41.9% | large |
| nis2compass | 62.41% | small |
| *(remaining 8 platforms)* | **not yet measured** | unknown |

**Action before estimating further:** run coverage on all 11 platforms
(1 day of CI/tooling work) to get real numbers before committing to a
timeline — "40% → 70%" on a large codebase is routinely 1–3 weeks per
platform of focused test-writing, so the total could range from 2 weeks
(if most platforms are already close) to 2+ months (if apiguard/citadel's
~40% is typical). Do not skip the measurement step.

## Phase 4 — CI green and stable (ongoing, verify after Phases 0–2)

No fixed time cost — this is a verification gate, not new work. Definition
of done: `Ecosystem CI` passes on 3 consecutive pushes to `main` with no
new failures introduced. Re-run after each phase above; every phase so
far in this remediation has surfaced a check that had *never* actually
executed successfully before (black, isort, eslint, golangci-lint were
each silently broken from day one) — assume more of these exist until
proven otherwise by a genuinely green run.

## Definition of "v1.0.0 — actually true"

| Condition | Status today |
|---|---|
| Phase 0 (security) closed | ✅ done |
| Phase 1 (docs match code) closed | ⬜ not started |
| Phase 2 (no silent governance bypass) closed | ⬜ not started |
| Phase 3 (≥70% coverage, all 11 platforms) closed | ⬜ not started — not yet even measured everywhere |
| Phase 4 (CI green, 3 consecutive runs) | ⬜ not yet achieved once |
| Phase 5 items | ⬜ per-item decision needed (build or explicit defer) |

**Bottom line:** Phases 0–1 (~2–3 days combined) fix what's cheap and
urgent. Phases 2–4 (~1–2 months, mostly Phase 3) are what actually stands
between the current state and the coverage/stability bar CLAUDE.md itself
sets. Phase 5 items can ship after v1.0.0 as documented roadmap work
without compromising honesty, *as long as ROADMAP.md and platform READMEs
say "planned" instead of claiming they're done* — which Phase 1 already
fixes.
